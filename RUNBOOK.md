## Standing rules

- Branch from `origin/main`; one PR per job; the PR carries the proof (validators, screenshots, link checks).
- Never a bare `wrangler deploy`. Production is reached only through `~/bin/land` (merge → watch main → deploy) or a script named under **Danielle may run**.
- Schema changes only through migrations that ship in the deploy; a `wrangler d1 execute` is run only by a script named below.
- Secrets are NAMES here and VALUES in the vault; never in this file, a commit, a log or an email.

## How to make a change

1. Read this file, then the request.
2. Make the change in your own worktree; run the repo's checks: `node site/scripts/check-site.mjs && node site/scripts/check-site.mjs --self-test && node --test site/test/*.test.mjs`, plus `npm run validate:instagram-loop` and `npm run validate:threads-loop` when the social loops or `data/social/` change. After `site/config/store.json` or a page changes, `node site/scripts/apply-cta.mjs` (never hand-edit the store box).
3. Commit with what changed and why; push; open the PR. Land through ~/bin/land on green, as the lane does; a change that is not publish-ready previews first.

## Deploy

- **Website:** every push to `main` that touches `site/**` or `.github/workflows/site.yml` runs `.github/workflows/site.yml`: the checks, then `wrangler d1 migrations apply peace-be-still --remote` (additive migrations in `site/migrations/`), then `wrangler deploy` from `site/`, then a smoke test of the live pages, the www redirect, `/api/social-visits` (page visits and the store-tap block) and `/go/app-store`. Landing through `~/bin/land` IS the deploy; never deploy by hand.
- **Chat Worker:** only `npm run worker:deploy` (`scripts/worker-deploy.sh`), under the Boss OS vault, after land.
